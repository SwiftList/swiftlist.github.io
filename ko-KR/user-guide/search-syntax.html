검색 문법 ​

SwiftList의 쿼리 상자는 단순 입력 이상을 지원합니다. 아래의 모든 연산자는 같은 쿼리 안에서 일반 퍼지 검색어와 함께 조합할 수 있습니다.

퍼지 매칭 (기본값) ​

이름의 일부를 입력하면, 그 문자들이 파일/폴더 이름 어딘가에 순서대로 나타나기만 하면 SwiftList가 찾아냅니다 — 연속된 부분 문자열을 입력할 필요가 없습니다.

입력매칭 결과
swlstSwiftList.exe
reportQ3-report-final.docx

설정 → 일반 → 시스템 → 퍼지 매칭 사용에서 이 옵션을 끄면, 연산자가 없는 일반 검색어는 연속된 부분 문자열로 나타나야 합니다 — abc는 더 이상 a-b-c에 매칭되지 않습니다. 아래 표의 모든 연산자는 이 설정과 무관하게 동일하게 동작합니다. 이 설정이 바꾸는 것은 일반 검색어 자체에 대한 요구 사항뿐입니다. ' 연산자는 이 설정과 무관하게 해당 단어 하나만 정확성을 뒤집으므로, 설정 자체를 바꾸지 않고도 정확 매칭 위주의 쿼리 안에 퍼지 검색어를 섞거나 그 반대로 할 수 있습니다.

여러 단어 ​

단어를 공백으로 구분하세요. 각 단어는 결과 집합을 더 좁히며, 입력한 순서대로 단어가 나타날 것을 요구하지 않습니다.

report final

는 Q3-report-final.docx뿐 아니라 final-Q3-report.docx에도 똑같이 매칭됩니다.

대소문자 구분 ​

  • 모두 소문자인 쿼리는 대소문자를 구분하지 않습니다: myfile은 MyFile, MYFILE 등에 매칭됩니다.
  • 대문자가 하나라도 있는 쿼리는 해당 단어에 한해 대소문자를 구분하게 됩니다: MyFile은 MyFile에만 매칭되며 myfile에는 매칭되지 않습니다.

연산자 ​

접두사/접미사예시효과
(없음)report이름 어디서든 퍼지 매칭 (기본값).
!!temp이름에 temp라는 정확한 부분 문자열이 포함된 결과를 제외합니다(이 항목은 퍼지 매칭이 아닙니다).
''report이 단어 하나만 정확성을 뒤집습니다 — 퍼지 매칭이 켜져 있으면(기본값) 정확한 부분 문자열 매칭이 되고, 설정에서 퍼지 매칭을 꺼 두었다면 이 단어만 다시 퍼지 매칭으로 돌아갑니다.
'...''final report'단어 경계에 고정된 정확한 매칭입니다(더 큰 단어 안에는 매칭되지 않습니다).
^^IMG접두사 매칭 — 이름이 반드시 IMG로 시작해야 합니다.
$.pdf$접미사 매칭 — 이름이 반드시 .pdf로 끝나야 합니다.
^...$^readme.md$완전 일치 — 이름이 정확히 readme.md여야 합니다. 둘이 같은 단어를 감쌀 때만 해당됩니다. 서로 다른 단어에 붙으면 각각 독립적인 접두사·접미사 필터로 남습니다.
|report | summaryOR — 파이프 양쪽 중 하나에 매칭됩니다.

이들을 자유롭게 섞어 쓸 수 있습니다. 예를 들어 ^IMG !.png$ 2024는 IMG로 시작하고, 2024년의, PNG가 아닌 파일을 찾습니다.

OR 쿼리의 경우, 특정 결과에 실제로 매칭되는 모든 항이 그 이름에서 하이라이트됩니다 — 먼저 매칭된 항 하나만이 아니라요. 그래서 report | summary는 두 단어를 모두 포함하는 결과에서 두 단어 모두를 하이라이트합니다.

여러 줄 붙여넣기 ​

여러 줄로 된 텍스트(예: 스프레드시트나 텍스트 파일에서 한 줄에 하나씩 복사한 파일명)를 붙여넣으면, SwiftList는 이를 그대로 붙여넣는 대신 자동으로 OR 쿼리로 접습니다.

123
456
678

는 123 | 456 | 678로 붙여넣어져 셋 중 무엇이든 매칭됩니다. 빈 줄은 건너뜁니다. 일반적인 한 줄 붙여넣기에는 영향이 없습니다.

드라이브 지정하기 ​

쿼리를 드라이브 문자와 콜론으로 시작하면 결과를 그 드라이브로 제한한 뒤, 평소처럼 검색어를 이어서 입력할 수 있습니다.

d: report

는 D: 드라이브에서만 검색합니다.

경로 모드 ​

쿼리에 경로 구분자(\ 또는 /)가 포함되어 있으면, SwiftList는 경로 모드로 전환하여 이름뿐 아니라 전체 경로에 대해 매칭합니다 — 알고 있는 폴더로 바로 이동할 때 유용합니다.

D:\Projects\SwiftList

끝에 구분자가 있으면(D:\Projects\) 정확히 그 폴더의 내용물을 검색합니다.

폴더 이름으로 필터링 ​

쿼리 끝에 ::<text>를 추가하면, 결과 자신의 이름이나 상위 폴더 중 하나가 추가로 <text>와 매칭되어야 한다는 조건이 붙습니다(다른 모든 곳과 마찬가지로 병음을 포함한 퍼지 매칭입니다).

1080 ::wallpapers

는 정확한 경로를 알거나 입력할 필요 없이, wallpapers와 매칭되는 폴더 어딘가에 있으면서 이름에 1080이 포함된 파일을 찾습니다. 여러 필터를 쉼표로 결합할 수 있습니다: report ::2024,:final.

단어가 파일이 아니라 폴더를 가리킬 때 ​

쿼리의 단어들이 파일/폴더 이름으로 전혀 매칭되지 않으면, SwiftList는 자동으로 다시 시도하여 단어가 상위 폴더에도 매칭될 수 있도록 합니다 — 특별한 문법이 필요하지 않습니다.

d01j dcj

는 dcj가 파일 자신의 이름에는 전혀 나타나지 않더라도, d01j라는 이름의 파일이 dcj라는 이름(또는 그 별칭)의 폴더 안에 있으면 찾아냅니다. 이는 파일 자체의 이름으로 채워지지 않은 나머지 부분을 그 파일 위의 폴더들로 보충할 뿐입니다 — 적어도 하나의 단어는 여전히 파일 이름 자체에 매칭되어야 하며, 이는 일반적인 이름 검색이 완전히 빈 결과를 반환했을 때만 작동하므로 일반 검색이 이미 찾아냈을 결과를 밀어내거나 순서를 바꾸는 일은 결코 없습니다. 상위 폴더는 파일 이름과 똑같은 방식으로 매칭되므로, 병음도 여기서 중국어 폴더 이름에 닿을 수 있습니다.

특정 검색에 대해 제외 규칙 우회하기 ​

쿼리를 *로 시작하면 설정을 바꾸지 않고도 그 검색에 한해 제외 규칙(ExcludedPaths, 무시된 글롭, 무시된 정규식)을 넘어서 검색합니다.

*node_modules

* 자체는 매칭 전에 제거되므로, 검색 텍스트의 일부로 취급되지 않습니다. 이는 이미 인덱싱된 결과만 드러낼 뿐입니다 — 애초에 인덱싱된 적이 없는 폴더(네트워크나 WSL 드라이브의 제외된 폴더)는 여전히 나타나지 않습니다. 숨김/시스템 파일은 어느 경우든 계속 필터링됩니다 — 이는 오직 여러분 자신의 제외 규칙 설정에만 영향을 줍니다. 뒤에 아무것도 없이 *만 입력하면, "검색 결과 없음" 대신 "계속 입력하여 검색하세요"라는 안내가 표시됩니다. 아직 실제로 검색이 실행되지 않았기 때문입니다.

결과 유형 트리거 ​

선택 사항이며 기본적으로 꺼져 있습니다 — 문자는 직접 지정합니다. 설정 → 일반 → 퀵 검색 창 → 결과 유형 우선순위에서 결과 유형에 트리거 문자를 지정해 두었다면, 퀵 창에서 맨 처음에 그 문자를 입력하면 그 유형의 결과만 표시됩니다 — 애플리케이션, 설정, 특정 File Filter 하나, 플러그인 자체의 항목, 또는 일반 파일 — 다른 모든 유형은 숨겨집니다.

;vs

는 ;가 그 유형의 구성된 트리거라면, 다른 어떤 유형의 결과가 그 텍스트에 더 잘 매칭되었을지와 무관하게 애플리케이션 중에서만 "Visual Studio"를 찾습니다. 트리거 문자만 입력하고 뒤에 아무것도 없으면, "검색 결과 없음" 대신 그 유형의 이름을 담은 안내가 표시됩니다. 즐겨찾기와 기록은 트리거 여부와 무관하게 영향을 받지 않습니다 — 항상 가장 먼저 나옵니다. 기본적으로 설정된 트리거는 없습니다. 설정 방법은 일반 설정을 참고하세요.

중국어 파일명: 병음 별칭 ​

중국어 문자가 포함된 파일명은 별도의 설정 없이도 자동으로 병음으로 검색할 수 있습니다.

  • 전체 병음: chongqing을 입력하면 重庆라는 이름의 파일에 매칭됩니다.
  • 이니셜: cq를 입력해도 重庆에 매칭됩니다(각 음절의 첫 글자).
  • 다음자(하나 이상의 유효한 발음을 가진 문자)는 흔히 쓰이는 각 발음에 대해 별칭을 생성하므로, 여러분이 떠올린 어떤 발음이든 매칭될 가능성이 높습니다.

이는 번들로 제공되는 별칭 플러그인이 처리합니다 — 활성화되어 있는지 확인하고 싶다면 설정 → 플러그인을 참고하세요.

즐겨찾기, 커스텀 별칭이 아닙니다 ​

SwiftList에는 범용적인 "직접 별칭/매크로 정의" 시스템이 없습니다. 가장 가까운 대안은 즐겨찾기입니다. 폴더, 파일, URL을 커스텀 표시 이름으로 고정해 두면 그 이름으로 검색 가능해집니다(결과에는 ★ 표시가 함께 나타납니다). 만약 실제로 원하는 것이 프로그램을 실행하는 커스텀 키워드라면, 대신 커스텀 명령을 참고하세요.
