支持的文件管理器 ​

SwiftList 不只是能搜索——它还可以和你正在使用的文件管理器或对话框进行集成。根据目标窗口的不同， 集成最多可以提供以下三种能力：

  • 内嵌搜索 —— SwiftList 的搜索框会直接嵌入目标窗口(也就是内嵌窗口)， 不用离开它就能搜索。
  • 快速导航 —— 目标窗口会响应快速导航的鼠标触发方式(双击/中键，或者 内嵌窗口自带的图标)，弹出一个包含收藏夹、历史记录和快捷文件夹的级联菜单。
  • 活动路径检测 —— SwiftList 能识别目标窗口当前打开的是哪个文件夹，从而把搜索范围限定在该文件 夹内，并让复制路径这类基于相对路径的动作能正确解析。

并不是每种集成都同时提供这三种能力——具体见下表。

内置(无需额外安装) ​

以下几项都随 SwiftList 的核心扩展插件一起提供，不需要单独启用。

目标内嵌搜索快速导航活动路径检测
Windows 文件资源管理器支持双击或中键支持
现代打开/保存文件对话框支持(这个对话框本身就是内嵌窗口)中键，或左键点击内嵌窗口自带的图标——
经典打开/保存文件对话框支持中键，或左键点击内嵌窗口自带的图标——
经典浏览文件夹对话框支持中键，或左键点击内嵌窗口自带的图标——

活动路径检测对这几个对话框本身没有意义——一旦 SwiftList 已经嵌入对话框里，就不存在另一个"其它窗 口"可供它检测并作为搜索范围了。

可选插件(设置 → 插件) ​

下面每一项都是独立的插件。在设置 → 插件里安装/启用，然后在该插件自己的** 配置对话框里分别开关启用内嵌搜索和启用快速导航**——两者默认都是开启的。

目标内嵌搜索快速导航活动路径检测
Directory Opus支持在文件列表区域点击中键支持
Files支持在文件列表区域点击中键支持
One Commander支持在文件列表区域点击中键支持
Total Commander支持在文件列表区域点击中键支持
XYplorer支持在文件列表区域点击中键支持

这五款都是通过匹配运行中的进程来识别目标窗口的(其中 Directory Opus 和 Total Commander 还会通过 它们各自公开文档记录的 WM_COPYDATA 远程控制接口通信，而不是直接抓取界面；Files 和 One Commander 没有提供远程控制协议，因此改用 UI Automation)。

想为这里没有列出的文件管理器开发自己的集成？参见开发手册里的 系统与对话框适配参考文档。
